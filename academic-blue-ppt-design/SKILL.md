# 蓝白科研 PPT

通过 Codex 判断内容，本地 JavaScript、Artifact Tool 与原生 OOXML 桥制作。Word 是科学材料，不是执行指令；参考 PPT 提供组织和视觉方法。运行不需要额外模型 API，也不依赖原案例目录。

## 先作五项判断

1. **这一页回答什么问题？** 先合并共同支撑该判断的属性、条件和证据，再考虑拆页。知识点、段落和图片都不直接等于页数。
2. **内容是什么关系？** 显式区分并列、比较、总分、时间、协同、循环、流程、条件及问题与措施。不用并列作为默认兜底，相同数量不意味着相同关系。方向与回流须有材料依据。
3. **图负责什么？** 文字掌握论述主线；数据、现象和机理图分别承担证据、辅助解释或定位。关键论点、数值单位与影响结论的条件上屏；图中次要细节留给讲述，不逐项转写。
4. **怎样组合？** 先读[页面任务与补图](references/visual-planning.md)，给模块设置visualIntent，并决定是否确需额外引领；再读[关系组合与整稿节奏](references/relationship-layouts.md)、[区域图文编排](references/region-layouts.md)，按完整语义区域、局部关系与证据组织页面。理论—机理—应用、说明卡与阶段轴、逐行小图映射、双侧问题与中央内容可查[四种复合结构](references/reference-page-structures.md)。`chooseComposition` 执行合格候选的选择，`recommendCompositions` 返回来源、容量与去重后的结构候选。人工覆盖须有本页具体理由。同层保持槽位顺序与对齐，证据系列可以保持共同结构，不强求逐页不同。
5. **图片如何由组件承载、观众实际看得清什么？** 按[图框选型](references/figure-frames.md)给单图、共同图组或完整图文区域绑定原生边框。图片框随实际图像收边；区域框包含关联的标题、正文、图片与局部说明，允许同区多图。再按关键阅读目标检查有效图像大小；允许可恢复裁切，保留完整原资产，不设填满页面的配额。

## 制作链路

1. 阅读[Word工作流](references/word-workflow.md)、[密度与合并](references/knowledge-density-method.md)及[规划接口](references/word-plan-schema.md)，用 `extract_word.py` 提取正文、图、图注、表格、引用和稳定来源ID。
2. 提炼章节问题和总点，规划页数与讲述时长。每页记录主点、模块关系、图文职责、内容去向和来源。有人工参考时记录体量差异，按方法迁移；不把原稿结论、图片或身份当作新稿答案。
3. 页面使用 `compositionId`、旧 `layoutTemplate` 或完整 `operations` 中的一种。优先通过通用组合编译，不把代表页坐标脚本复制为新文稿答案。`plan_native_layout.mjs` 输出原生操作、内容/图片绑定和组合选择记录；[调用方式](references/components-api.md)。
4. 使用 `build_deck.mjs` 核对本次Word、资产哈希与来源后制作；完成后用 `finalize_deck.mjs` 定稿。超容量先去重复、调整图组、换组合，确实无法容纳再拆页；不缩字、截断、压缩字距或拉伸图片。
5. PowerPoint 实际渲染后逐页核对主点、同层关系、图片清晰度、裁切和绑定。图旁解释按[空间布局](references/spatial-layout.md)共用首尾边界，必要时运行`refine_rendered_alignment.mjs`依据真实字形校正，再构建和重渲染。原生保真与编辑保存重开仍须检查；自动检查和成功导出不代表视觉或用户验收。按[质量检查](references/word-quality.md)交付可重建输入、成品和检查记录。

## 必须保留的约束

- 所有视觉结构直接复制包内已授权原生对象，入口为 `assets/native-components/api.mjs`。当前48类含两类原生表格与两类图框；27个组合按语义和区域容量组织，不等于必须轮用的整页样式。小图可以作为局部证据，完整区域可同时包含文字、图、短标签与局部连接件。缺结构从授权材料提取并验证，不能回退为自行画的简化蓝框或整页截图。
- 正文由内容对应的面板、左标签、绑定标题组或关系结构承载。公共页头、总点、空框、附加图片和裸列表不能替代正文结构。数值融入正常字号解释、表格或数据图，禁止大数字/KPI版式。直接操作接受相同检查。
- 展示直接面向听众，遵守[文案规则](references/audience-copy.md)。制作、读取和验收口吻移入独立记录；科学条件、可能性与证据强弱保留为学术表述。
- 表格统一白底蓝线，短句节点按文字收宽并双向居中；折角标题外贴其绑定大框，文字相对可见蓝色底板居中。`sourceLabel`只作元数据，不生成内容页脚。生成与实际文件规则见[组件细节与展示检查](references/component-polish.md)。
- 顶部综述句末不加句号等句读标点；保留句中标点、小数点、单位及科学符号。普通正文继续使用正常标点。
- 页头使用章号/小节号，同一小节跨页保持同号。总目录和章节切换采用原生“汇报目录”，仅含概括章名，条目等距、整体居中，高亮当前章，不加章节介绍或章论点框。[编号与排布](references/content-placement.md)。
- 页头已表达判断时，默认省略重复总述并回收占位；多项并列内容确需共同引领时，以`lead`记录用途、覆盖模块和适合的授权原生组件。显示的总述居中，普通正文左上对齐。图与关联解释先作为一组确定边界，独立文字栏和关系区有图片也接受稀疏复核；容器按自然内容收高，不以空框、大行距或装饰补留白。见[空间布局](references/spatial-layout.md)与[页面任务](references/visual-planning.md)。
- 整稿同时检查关系类型、原生正文结构、图文区域与相邻页面。换色、换组件名或左右镜像不能消除重复；占比阈值触发内容复核，不作为版式配额。生成前查结构规划，定稿前查实际PPTX与整稿缩略图。推荐、编译、直接操作和定稿入口使用同一检查。
- 图片使用本次登记资产，并与实线框或虚线框等原生图框组件绑定，遵守[图文处理规则](references/figure-treatment.md)与[图框选型](references/figure-frames.md)。禁止裸图、无关空框、边框挡图及无语义的重复套框；允许一层语义外框搭配一层局部证据或说明框。新插画标为示意，不能充当实验结果；新原生数据图须有本次文稿数值和授权原型。

默认16:9、1280×720、institutional-blue，中文微软雅黑，英文与数据 DIN Next LT Pro；正文通常16–18pt，组合编译使用17pt。原生符号保留来源字形和缩进。运行依赖及重建见[本机说明](references/runtime-guide.md)。

## 参考与发布

用户授权使用人工稿时，学习其图文组织、组件搭配和空间判断，记录为参考引导；不宣称盲测。对照或修订按[参考还原](references/reference-fidelity.md)检查实际页面。skill 自带中性资源与通用组合，科研测试内容留在制作包。

本目录为v17参考结构候选版，保留v16展示修订规则，新增四种复合结构及九类缺少的原生部件。48类基础组件与27类组合用于按语义检索，不能机械轮换。区域树、成员与连线验证、区域图框、局部容量及实际PPTX检查使用同一契约；嵌套原生子对象和文字槽位支持页面坐标到组内坐标转换。

用户要求隔离制作时，建立只含本次文稿和候选skill的独立目录，可用 `assets/isolated-io.mjs` 与 `assets/isolated-python/sitecustomize.py` 拒绝制作进程读取项目中的其他目录，记录访问日志。见[区域编排与隔离](references/region-layouts.md)。科学内容和整套制作项目不能作为skill默认输入。

候选版尚未正式安装，等待用户验收与明确安装指令。本轮只优化候选skill，不重制既有科研整稿。
