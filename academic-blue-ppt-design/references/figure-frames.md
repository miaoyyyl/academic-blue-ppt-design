# 插图与原生图框共同选型

图片不是默认裸放。规划图片用途时，同时确定单图框或共享图组框；这一步属于图文结构，不是最后随机加装饰。图框不能替代正文组件，也不计入自然内容高度、有效图片或留白充实度。

## 原型与参考方法

| 参考 | 采用的方法 | 包内类型 |
|---|---|---|
| 人工微塑料稿第20页，原生对象22 | 蓝色实线外框把图像与同一论证区域收成一组；保留原线宽、直角和轻阴影 | `human-figure-frame-solid` |
| 人工镉污染稿第7、15页 | 图和所属解释在同一栏内，框线范围与栏目任务一致 | 图文归属和同层一致性，不复制其科学内容 |
| materials白蓝模板第3页，原生对象52 | 细虚线圆角框标识共同信息范围；本次迁移为辅助图或共享图组容器 | `materials-figure-frame-dashed` |
| materials重点结题模板第6、7页 | 共享外框界定整体组，组内保留明确关系 | 共享图组方法，不向无顺序的图片擅自添加箭头 |

原生对象的几何、线宽、线型、填充和效果来自授权PPT。提取时仅将源主题颜色解析为实际RGB，避免换母版后变色；记录源文件哈希、页码、对象ID和主题映射。制作或搬移重建无须访问原参考目录。

## 选择顺序

1. **独立照片、设备、数据证据：** 默认实线框，形成清晰阅读单元。论文多面板整图用一个外框；内部子图原有框线不再重复套框。
2. **辅助机理示意：** 可用细虚线框，保留“示意图”等标注；虚线不自动表示科学不确定性。描述证据强弱仍以正文为准。
3. **多图共同支撑一项论述或共同构成比较：** 可使用共享虚线框，记录共同用途；不同独立栏目的图片通常各有单图框。不要为了换线型把同层照片任意分开。
4. 已有原生图组容器时优先复用；如它已经符合图片绑定和边界检查，应登记为图框类型后调用，避免重复边框。图片内部印刷边线不能取代可编辑组件绑定。

## 接口

单图在 `supportFigures[]` 中写：

```json
{"frame":{"style":"solid","padding":4,"reason":"独立装置照片与本栏应用说明绑定。"}}
```

组合编译默认补入匹配的原生框，不改变文字字号或图片宽高比。框放在图像后方，图片显示区域内缩4px，再按实际显示边界向外加4px；图注在框下方，不能压线。`padding`只接受2–12px。

`text-over-figures` 共享图组通过 `compositionOptions.figureFrame` 设置：

```json
{"scope":"group","style":"dashed","padding":4,"reason":"三幅界面图共同支撑本页的机制比较。"}
```

共享框仅包围实际图片的并集，不包住上方整排文字，也不保留每幅的重复外框。共享图组预留共同的实际图注高度，各图图注齐到外框下方。`peer-figure-columns` 中各栏有独立的图文归属，保留单图框，防止跨栏框穿过正文。关系、来源和阅读目标照常保留。

编译后的每图包含 `frameOperationId/frameStyle/frameScope/framePadding`；框操作含 `figureFrame.figureIds`、用途与间距。直接写 `operations` 必须补齐相同绑定，不能只写一个无关蓝矩形或把图框声明为已通过。

## 验收

- 推荐、组合编译、标准制作、直接原生制作和定稿均拒绝无框内容图、失效绑定、孤立框、重复绑定、错误层级与过大空框。
- 实际PPTX读取图片和框的真实边界、层级、可见线型、颜色及粗细；删除描边、改成透明线、移动或放大框都应失败。
- 边框应随图片/图组一起移动；图片仍独立保留可恢复裁切与完整源图。正文、有效图片面积和空间布局指标不能把空框作为内容。
- PowerPoint渲染后逐页检查：不遮挡图像标注、不切边、图注不压线、同层使用一致，不机械套用大面积装饰。
- 修改原生框线与图片后保存重开，确认可编辑性。结构检查通过仍需视觉检查及用户验收。
