# 表格、短句节点、折角标题与展示文案

## 默认外观与对齐

- 原生比较表和问题措施表使用`tableAppearance: 'uniform-white-blue'`，关闭行列条纹，单元格统一不透明白底。保留源表边线与原生可编辑结构，表头蓝字加粗。不要继承交替行底色。
- 条件/输入/汇合结果属于短句节点，水平、垂直居中。节点宽度按固定字号下的文字宽度与左右内边距计算，同层输入等高，结果居中收宽；不要求所有框宽相同，不把结果框默认拉满整栏。
- 输入框和结果框收宽时，原生箭头位置随真实节点中心调整。换行通过增高或重组解决，不缩字、压字距。
- 这些规则不改变长段正文的左对齐、靠上规则，也不把承载多段解释和图片的区域框收成短句宽度。

## 折角标题

区域中`headingStyle: 'folded'`通过`headingAttachment`绑定自己的区域框，默认向左外伸14px。折角与侧边咬合；只有绑定标题可在8–24px内有限外伸，普通文字和图片没有越界豁免。

标题文字相对原生蓝色底板居中，排除折角尾部与阴影。默认20pt时可见底板至少44px高，整组高度保留折角。正文起点跟随标题实际高度。长短标题按文字收宽，不能只对整个组件设置居中。

`assets/component-polish.mjs`在区域编译、关系组合、旧兼容路径和直接原生API中共享布局。原生子对象使用页面坐标，通过`global_to_parent_box`转换后定位；保留源对象形状、旋转、线和效果。

## 展示文案

`sourceLabel`是制作元数据，不自动生成内容页脚。内容页不输出通用汇报名或来源核验、提取、验收说明小字。制作记录保存在独立QA文件；文献集中在参考页，必要科学条件以正常字号并入对应正文。备注只保留真实文献和讲述补充，不堆放验收过程。

图内的单位、坐标、图例、数据标记和必要科学标签仍保留。不能按“小字号”或“灰色”简单全删科学信息。

## 实际文件与渲染检查

`auditComponentPolish`接入共用组合检查。实际PPTX读取表格填色/条纹、文字锚定、子对象与蓝色底板坐标，拒绝残留条纹、顶部文字、过宽节点、内缩折角、偏下文字和内容页脚。

`render_check.ps1`在有规划和绑定时自动调用`verify_rendered_component_polish.py`，比较PowerPoint真实字形边界与可见节点/底板的中心。当前容差为1280×720坐标下4px，同时检查文字容纳；这不替代逐页视觉核对。

回归入口：

```text
node scripts/test_component_polish.mjs
node scripts/run_region_regression.mjs qa/regression
node scripts/test_pptx_component_polish.mjs deck.pptx plan.json native-bindings.json qa/actual-negative
```

原生表格受控外观在写入和保真比较中使用同一函数，不能通过忽略全部填色差异来通过检查。实际文件反例包含条纹开关、残留单元格色、顶部锚定、结果框过宽、标题内缩、文字偏下和额外页脚。
